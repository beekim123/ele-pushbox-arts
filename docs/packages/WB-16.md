## 要做的
1. **`game` 字段加一个值 `"frozen_v1"`**（游戏里有，但属于已冻结、要重做的 v1）：
   - 公共页面仍在用 → `in_use`：`lobby`、`settings`、`controls`、`dialogue`。
   - 关卡 v1 → `frozen_v1`：`chapters`、`levels`、`play`、`pause`、`hint`、`rulecard`、`complete`。
   - 配送 v1 → 只读核对游戏代码后标 `frozen_v1`。线索：`live_hud.gd` 注释写的是 `delivery_hud@v4`；`live_*` 里引用的 UI-12a（`run_door`、`run_door_skull`、`run_map`）、UI-12b（`run_shelf`、`run_rest`、`run_quit`、`run_event`、`run_result`）、UI-12c（`run_wish_card`、`run_lucky`、`run_wish_give`）；以及 `reels`、`settlement`。在代码里找不到对应的页面保持 `not_yet`，`notes` 写原因。
   - 剧情、伙计页面保持 `not_yet`。
2. **加「待设计」条目**（`art: null`，`notes` 必须写来源）：
   - `lobby_modes` 多模式大厅：`flow` 开始，`game: "not_yet"`，`notes` 写「游戏仓库 CORE-01 交付要求；现在游戏在旧大厅上用代码加入口」。
   - 配送 v1 里有、HTML 没有设计稿的页面：读 `live_*.gd` 的开头注释和标题文字，凡是不对应任何 `ui.screen.*` 的页面各建一条，`game: "frozen_v1"`，`notes` 写游戏文件名和「v1 直接在游戏代码里做的，重做时先补设计」。只看文件开头注释和标题文字，不通读代码；拿不准的列进交付「问题」，不建条目。
   - 新关卡线（`flow`「新关卡线（设计中）」）：`new_play_keys` 新操作的按键提示、`new_controls` 新操作的操作说明页、`hud_tools` 本关工具图标；`game: "not_yet"`，`notes` 写「暂定，等操作方案确认后再画（docs/design/gameplay/README.md）」。
   - 只写页面名称、用途和来源，不写玩法数值、关卡或房间数据。
3. **`tools/screens.mjs`**：`build` 把 `art: null` 的页面算作「缺设计」，后四步都算未开始；`check` 接受 `frozen_v1`，要求 `art: null` 的条目有 `notes`；49 个 `ui.screen.*` 全覆盖的检查不变。
4. **界面清单页**：
   - 最上面单列一组「待设计（N）」，按来源分小组；每条显示「缺设计」标记、来源说明。
   - 五步进度的标记按状态上色并给图例：已完成（绿）、只有参考图 / 部分（黄）、未开始（灰）、缺设计（红）；颜色在浅色、深色外观下都要看得清，不能只靠颜色（同时有 ✓ / ○ / ! 之类的符号）。
   - 「游戏接入」一列显示：在用 / v1 已冻结 / 未接入。
   - 总览「内容缺口」改成：待设计 N 个、Godot 未实现 N 个、游戏未接入 N 个、v1 已冻结 N 个。
   - 原样预览（WB-14）里点到「待设计」的页面，照旧显示「此页还没画」占位卡，并写来源。
