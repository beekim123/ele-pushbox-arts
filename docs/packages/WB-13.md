## 目标
`content/screens/screens.json` 里配送、一局流程、剧情、伙计页面的跳转都填上；原样预览页能切到配送模式，从滚轮台一路走到结算。

## 要读的（只读这些）
- 本仓库：`content/screens/screens.json`、`docs/packages/WB-11.md`（字段说明）、`workbench/js/app/play.js`
- 游戏仓库（私有，**只读，不改不推**；本机副本位置以用户机器为准，找不到就 `git clone https://github.com/beekim123/ele-pushbox.git` 到仓库外的临时目录）：`docs/design/mode-delivery.md`、`docs/design/delivery-run.md`、`docs/design/mode-story.md`，必要时 `docs/design/delivery-slice.md`、`docs/design/characters.md`

## 要做的
1. 从游戏仓库的设计文档整理配送模式、一局流程、剧情、伙计各页面之间的跳转（游戏代码里大多还没有这些页面，以设计文档为准）。
2. 填进 `screens.json` 里已有的 `not_yet` 条目：`transitions`（`key`、`focus`、`label`、`to`、`when`、`hotspot`）。`hotspot` 从本仓库的实际画面上量。
3. 文档没写清、或文档之间矛盾的跳转，**不要猜**：在交付里列成「待定」问题清单，写明出处（文件和小节）；清单里这些条目先 `to: "@stay"`，`notes` 写「待定」。
4. 大厅进入配送 / 剧情的入口，按设计文档接到对应的大厅变体（`lobby_story`、`hub_start` 等）。
5. **公开范围**：美术仓库是公开的。只写「哪个按键 / 按钮去哪个页面」和条件的一句话说明；不写玩法规则、数值、概率、剧情正文、关卡或房间数据。
6. `game` 字段：看游戏仓库 `main` 现在是否已经接入这些页面（模块隔离队列的 BR-05 会把配送分支合进 `main`）。以 `game/modes/*/art.json`（CORE-06 之后才有）或代码里出现的 `art:ui.screen.<名>` 为准；拿不准的保持 `not_yet`，写进「待定」。
7. `play.html` 的模式切换启用「配送」；局内配送 HUD（`ui.screen.delivery_hud`）只展示，按 C 模拟送达 → 结算。没画的目标页面照 WB-12 显示占位卡。
8. **暂停点**：验收全部通过后、合并推送前，把新增跳转表全文和「待定」清单发给用户，等用户回复同意公开；用户要改就改完再问一次。
