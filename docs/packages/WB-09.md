## 背景：实测原因
1. **窄窗口详情看不到**：`workbench.css` 的 `@media (max-width: 1100px)` 把 `.view > .info` 排到网格最后一行。资产与动画页点一张卡片，详情 `#asset-inspector` 实际出现在所有卡片之后：1100px 宽时在页面约 y=15000px，1024px 宽时约 y=18500px，看起来像点了没反应。
2. **确认页一打开是空的**：默认筛选「待确认」，而现在待确认 0 项（已确认 297、草稿 7），所以只显示「没有符合条件的资产」。
3. **地图概念大多只有文字**：80 张地图里 26 张没有注册概念场景（`window.PB_CONCEPT_SCENES` 里没有），卡片上只剩一个约 960×540 的虚线空框；72 张没有静态概念图。
4. **拆仓留下的断链**：概念卡「机制」一栏链接到 `#mechanisms/<id>`，但美术仓库没有机制页，也没有机制数据（`PB_CONTENT` 里只有 `concepts`），点了会跳回场景页；`main.js` 里 `#maps` 重定向到不存在的 `#rooms2/pool`。
5. 资产与动画的分类按钮里 avatar / cargo / monster / scene 直接显示英文：`assets.js` 的 `CAT` 没有这四项（`mode-resources.js` 里有）。

## 目标
任何窗口宽度下点卡片都能马上看到详情；确认页打开就有内容；只有文字的地图概念收起来，不再显示大空框；页面里没有点了会跳错的链接。

## 要做的
1. **窄窗口详情**：宽度 ≤1100px 时，详情作为右侧抽屉打开，可关闭，Esc 关闭，焦点回到原来那张卡片；720px 以下抽屉占满宽度；宽窗口保持现在的三栏不变。场景页的 `#scene-info` 同样处理。
2. **确认页**：有待确认时默认「待确认」；为 0 时默认「全部」，顶部写「当前没有待确认的美术」，并给出最近批次和「草稿 N 项」的快捷入口。用户手动选过的筛选在本次打开期间保持。
3. **地图概念折叠**（以 `window.PB_CONCEPT_SCENES` 是否注册为准，不写死名单）：
   - 概念总表分两组：「有概念场景」照常；「只有文字（N）」默认折叠，可展开。
   - 总表加「完整度」列：概念场景有 / 无、静态概念图张数。
   - 左侧菜单的地图概念分类同样：只有文字的收进一个默认折叠的「只有文字（N）」子组。
   - 只有文字的概念卡不再显示大虚线空框，改成一行「还没有概念场景」。
4. **断链**（只改 `workbench/js/app`）：
   - 概念卡「机制」一栏改成纯文字显示编号，不加链接。
   - 删掉 `main.js` 里 `#maps` → `#rooms2/pool` 的重定向，未知地址照常回到默认页。
   - 素材说明文字（`art/source` 里的 usage / notes）引用的游戏仓库文档属于冻结区，不改。
5. **分类中文名**：`assets.js` 的 `CAT` 补上 头像 / 货物 / 怪物 / 整幅场景；和 `mode-resources.js` 合并成一份共用（例如都用 `PBAssets.CAT`）。
