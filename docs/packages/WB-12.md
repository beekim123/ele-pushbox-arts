## 用户的话（2026-10-23）
「最后是有一个页面单独展示成和游戏一模一样的布局，跳转。」

## 目标
一个单独页面，只显示和游戏完全一样的画面和布局，能像玩游戏一样用键盘和鼠标在页面之间跳转，用来在进游戏代码之前看整套界面的流程。本包先做关卡模式（跳转表在 `content/screens/screens.json`，WB-11 已写好）。

- `workbench/js/app/views/scenes.js`（画界面、局内关卡回放 `level.M05` 的写法）
- `workbench/js/app/stage.js`（WB-08 之后的限帧规则）
- `workbench/index.html`（脚本加载顺序）

## 要做的
1. **新页面 `workbench/play.html`**：独立页，不带工作台菜单。工作台总览和「场景与界面」加入口「原样预览」。加载和 `index.html` 相同的 core 脚本和数据（可以把脚本清单抽成一个共用的加载文件，但不改 core 文件本身）。
2. **画面**：只显示 320×180 游戏画面，整数倍放大铺满窗口、居中、最近邻、四周黑边。直接调用工作台现有的画法：HTML 画面就是 Godot 实现时对照的标准。
3. **跳转**：从 `lobby` 开始，按 `screens.json` 的 `transitions` 走：
   - 键盘和游戏一致：方向键 / WASD 移动焦点（用新的 `state.focus` 重画本页）、Enter / Space 确认、Esc 返回、H 提示。Z / R 在局内只给一个短提示「预览不能真的玩」。**Tab 在游戏里是看全图，这里不占用。**
   - 鼠标：悬停 `hotspot` 移动焦点，点击等于移焦点再确认。
   - `@return` 按跳转历史回到来源页；`@quit` 显示「已退出（预览）」，按 Enter 回大厅；`@stay` 只重画本页。
   - 有条件的跳转（`when`）：在信息浮层里给开关，默认取最常见的情况（例如「有上次关卡」默认关）。
   - 局内 `play`：显示 M05 的设计模型场景加 HUD（复用场景页已有的关卡回放，不是 SDK 物理）。按 C 模拟过关 → `complete`（游戏不用 C 键）。
   - 目标页面在清单里、但 `art` 为 `null` 或还没有画面：显示占位卡「此页还没画：<名称>（<id>）」，Esc 返回。
4. **信息浮层**：按 I 显示 / 隐藏（游戏不用 I 键），默认隐藏，保证画面和游戏一样干净。内容：当前页面 id 和名称、五步进度、本页可用按键、「在工作台打开」（链到 `index.html#screen/<id>`）、跳转历史、条件开关、模式切换（关卡 / 配送；配送等 WB-13，先置灰）。
5. **地址跟随**：`play.html#levels?focus=2` 这样的地址能直接打开某页的某个焦点，刷新不丢；浏览器后退回到上一页。
6. **性能**：同一时间只画当前页；遵守 WB-08 的限帧和自动降帧；切页时上一页立即停画。
