「现在的 html 管理挺乱的，每个页面我都不知道在哪，怎么找。」用户同意按下面的结构改。

## 背景
- 左栏有 112 个链接：关卡模式 13、配送模式 13、地图概念 81、美术 6、声音 1。
- 「关卡模式·全部资源」（`#level-art`）、「配送模式·全部资源」（`#delivery-art`）、「美术·资产与动画」（`#assets`）三个页面展示的是同一批 304 项资源；模式下面的子菜单又和页面里的标签条重复。
- 默认首页是最重的场景页。

## 目标
左栏只剩 6 个一级入口，一眼能找到东西；三个重复的资源页合成一个资源库，筛选条件写在地址里；打开工作台先看到总览。所有旧地址都还能打开。

## 要做的
左栏只有下面 6 个一级入口，不再有二级长列表，可以带计数徽标：
1. **总览 `#home`**（新的默认首页）：资源总数、已确认、待确认、草稿；最近 3 个确认批次；声音条数；内容缺口提醒（只有文字的地图概念 N 张；「Godot 未实现的界面 N 个」先留位置，WB-11 补数据）；其他入口的快捷链接。
2. **资源库 `#library`**：合并 `level-art`、`delivery-art`、`assets` 三页。
   - 筛选：模式（全部 / 关卡 / 配送，用 `mode-catalog.js` 现有的分类规则）、主题（随模式联动）、用途分组（角色与生物 / 物品与装饰 / 机关与特效 / 界面与引导 / 渡口·伙计·剧情）、资源类别、确认状态、搜索、是否包括通用资源。
   - 筛选状态写进地址，例如 `#library?mode=delivery&theme=diyu`，可以收藏，浏览器后退能用。
   - 卡片用 PNG（WB-08 的 `PBAssets.thumb`）。点卡片打开详情（WB-09 的抽屉 / 右栏），详情里保留「预览与动画」「编辑与对比」「加入确认清单」。
   - 卡片按素材原尺寸整数倍放大：16×16 精灵约 4–6 倍，320×180 画面 1 倍。1440×900 一屏至少看到 12 张，不再把 16×16 的小图放进 320×180 的大框。
3. **场景与界面 `#scenes`**：现在的场景页。「界面风格提案」（`#ui-proposals`）挪进来作为页面里的一个标签（WB-11 会在这里加界面清单）。
4. **确认 `#review`**：「导出」（`#export`）作为确认页里的第二个标签；顶栏「本地未导出修改」提示照旧链到导出。
5. **地图概念 `#concepts`**：页面里改成卡片墙，每张一卡（名字、文化、阶段、评价、有无场景、概念图张数），可按阶段 / 评价 / 完整度筛选；WB-09 的「只有文字」默认折叠保留。左栏不再列出 80 张地图。
6. **声音 `#audio/sfx`**：不变。

「编辑与对比」不再是一级菜单，从资源详情进入（`#edit/<id>` 地址保留）。

要求：
- **旧地址都保留并跳到新位置**，不能出现死链：`#level-art`、`#level-art/<分组>`、`#delivery-art`、`#delivery-art/<分组>`、`#assets`、`#assets/<id>`（跳资源库并打开详情）、`#edit`、`#export`、`#ui-proposals`、`#concepts/<id>`、`#audio/<…>`、空地址。写一张「旧地址 → 新地址」对照表放进交付，每条都有测试。
- `mode-catalog.js` 的函数和分类结果不改（`tests/mode-resources.test.mjs` 直接加载它），只是从「菜单」改成「筛选来源」。
