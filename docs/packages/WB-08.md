## 背景：实测原因
2026-10-23 在 Linux 4 核 Xeon、headless Chromium、file:// 打开时测得（你在本机先测一遍「改动前」）：
1. **列表页打开时主线程卡住**：配送·全部 2.6 秒，配送·地府 2.2 秒，配送·界面与引导 2.0 秒，资产与动画 2.8 秒，关卡各页 0.7–1.0 秒。每次搜索输入、每改一次筛选都再卡一次。
   原因：每张卡片都同步调用代码绘制 `PBAssets.thumb`。49 张界面画面合计 2.58 秒（`ui.screen.reels` 一张 219ms），200 多张精灵合计只有几毫秒。分页解决不了：每页 24 张时最差的一页仍要 1.5–1.9 秒。
2. **预览页停着不动 CPU 也很高**：场景·送达结算 100%，资产详情·大厅 99%，资产详情·主角 81%，场景首页 53%。
   原因：`PBStage`（`workbench/js/app/stage.js`）每个 requestAnimationFrame（60 次/秒）都整屏重画，而一帧要 25–200ms（`ui.screen.settlement` 54ms、`ui.screen.levels` 40ms、`ui.screen.reels` 199ms）。热点是每帧重算不动的背景（`terrain-diyu.js` 的 vnoise、`terrain.js` 的 rock、`env.js` 的 vignette）和面板（`ui-kit.js` 的 shrink）。美术规范的帧率是人物 8 fps、环境 4 fps。
3. 这些绘制文件在 `workbench/js/core/`，参与已确认画面的内容哈希，**不能改**。所以只改调度（什么时候画、画几次），不改画法。

## 目标
列表页打开不卡、搜索不卡；放大预览照样是代码实时绘制的动画，但停着不动时 CPU 很低；任何一帧画出来的样子和改动前完全一样。

## 要做的
1. **列表一律显示已生成的预览 PNG**
   - 文件是 `art/export/preview/<id>.png`：304 张都已在 git 里，由 build 生成，`verify` 已逐像素校验它们和源绘制一致。**不新增任何 PNG。**
   - 统一在 `PBAssets.thumb` 里改；调用方（资产与动画卡片、`mode-resources.js` 卡片、`review.js` 卡片）的显示尺寸保持不变。
   - 地址相对 `workbench/index.html` 为 `../art/export/preview/<id>.png`。
   - 精灵 PNG 是全部帧横排：宽 = `size[0]` × 帧数，第 i 帧在 x = i × `size[0]`。卡片仍显示现在那一帧（`firstFrame`：第一个动画的第一帧），用外层裁切加整数倍放大，`image-rendering: pixelated`。
   - 程序绘制类（theme / ui / screen / material）的 PNG 就是 320×180 整幅。
   - 用 `<img loading="lazy" decoding="async">`，写明宽高，避免布局跳动。
   - 本浏览器里有本地修改的精灵（`store.effective` 返回带 `_draft` 的），PNG 里没有这些修改，仍用 canvas 现画。PNG 加载失败也退回 canvas，并 `console.warn` 一次。
2. **点开放大的预览继续用代码绘制**（资产详情、场景页、编辑页的动画预览），改调度：
   - `PBStage` 不再每个 rAF 都画：精灵只在 `PB.sprites.frameAt` 算出的帧号变化时重画；程序绘制画面按帧率上限重画，默认 8 fps，`create` 选项里可传。
   - 自动降帧：连续测得单帧绘制超过 40ms 的画面降到 4 fps，超过 120ms 降到 2 fps，工具栏显示「性能模式 · N fps」。
   - 画面滚出视野（IntersectionObserver）、所在页面隐藏、浏览器标签切走时完全停画；同一时间只有一个预览在播放。
   - 可选：静止背景缓存。`scenes.js` 已经对第 2–5 章画面这样做（`drawChapterScreen` 拦截 `PB.uiStyle.backdrop`）。要推广到其他画面，必须先有测试证明同一 tick 下与不缓存的结果逐像素一致，否则不做。
   - 限帧只是少画几帧，不改变任何一帧的画法：同一 tick 下的输出与改动前逐像素一致。
3. **搜索和筛选不再重建卡片**：卡片只建一次，之后只切换显示 / 隐藏；搜索输入加 150ms 防抖。
4. **新增 `tests/workbench.perf.cjs`**（启动方式照抄 smoke，支持 `WB_HTTP=1`）：用 longtask 观察和 CDP `Performance.getMetrics` 测量下面「验收」里的数字，打印结果，超过门槛就失败（「三个最重画面」一项只打印、不失败）。
