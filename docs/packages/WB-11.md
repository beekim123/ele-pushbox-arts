## 背景
- 工作台里有 49 个界面画面（`ui.screen.*`，全部已确认），都是一张张独立的示意图，没有页面之间的跳转。它们分散在 4 处：场景页「游戏界面」分组、资产页「界面画面」、两个模式页「界面与引导」、「界面风格提案」（WB-10 后前三处已合并到资源库和场景与界面）。
- 2026-10-23 的游戏 `main` 只接入了关卡模式 11 个页面（大厅、章节、关卡选择、局内、暂停、提示、规则卡、过关、设置、操作说明、对话）。
- Godot 美术包（`godot/native-coverage.json`）里：16 个界面已实现，10 个配送界面只有参考图，23 个新界面（一局流程、剧情、伙计、配送教学、剧情大厅）没有条目。
- 模块隔离设计（游戏仓库 `docs/design/modules.md` 第 7 节）规定界面这类「组合」带 `owner` 归属（common / lab / delivery / story / hell），由美术仓库 ART-07 加。**本包不重复记录归属**。

## 目标
美术仓库有一份界面清单，作为「游戏有哪些页面、每页做到哪一步」的唯一来源；工作台「场景与界面」里按清单找到每个页面，每页一个固定地址，还能看到页面之间怎么跳。

## 要做的
1. **新建 `content/screens/screens.json`**（`"format": "pushbox.screens/1"`；不在冻结区，也不在 SNAPSHOT 里）。每个游戏页面一条：
   - `id`：游戏里的页面名，如 `"levels"`。
   - `art`：主画面编号，如 `"ui.screen.levels"`；变体写在 `variants`，如暂停的 `["ui.screen.pause_help"]`；没有画面的写 `null`。
   - `name`：中文名；`flow`：开始 / 关卡内 / 配送一局 / 剧情 / 伙计 / 设置与帮助。
   - `transitions`：`[{ "key": "Enter", "focus": 0, "label": "继续", "to": "play", "when": "有上次关卡", "hotspot": [x, y, w, h] }]`
     · `key` 用游戏按键：`Enter`、`Esc`、`H`、`Z`、`R`、`ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight`；
     · `focus` 是菜单第几项（从 0 开始），对应画法的 `state.focus`；
     · `hotspot` 是 320×180 坐标里的鼠标点击区域，从实际画面上量；
     · `to` 是页面 `id`，或 `"@return"`（回到来源页）、`"@quit"`、`"@stay"`（留在本页，如调设置、换章）；
     · `when` 写条件跳转的条件，没有就省略。
   - `game`：`"in_use"` 或 `"not_yet"`，游戏是否已接入。人工维护：以后游戏接入新页面时由合并方改。
   - `notes`：示例数据说明。
   - 另有顶层 `unlisted`：没有纳入清单的 `ui.screen.*` 和原因。
   - 只写「哪个按键 / 按钮去哪个页面」，不写关卡解法、剧情正文、玩法数值（美术仓库是公开的）。
2. **五步进度**，除「设计」和「游戏接入」外都由工具算，不手写：设计（清单里有这一条）→ HTML 画面（`art` 编号在 `art/export/manifest.json` 的 `assets[]` 里存在）→ 用户确认（该项 `current.status` 为 `approved`）→ Godot 实现（`native-coverage.json`：`implemented` / `reference_only` / 没有条目）→ 游戏接入（`game` 字段）。
3. **新建 `tools/screens.mjs`**（不要改 `tools/art.mjs`，它在资源包清单里）：
   - `node tools/screens.mjs build`：读清单、manifest、native-coverage，算出进度，写 `workbench/data/screens.js`（`window.PB_SCREENS = …`）；内容没变时不改文件。
   - `node tools/screens.mjs check`：每个 `art` / `variants` 编号存在；`to` 指向清单里的页面或 `@return` / `@quit` / `@stay`；`hotspot` 在 320×180 以内；49 个 `ui.screen.*` 每个都被某条引用，或写在 `unlisted` 里。有错时非 0 退出。
   - `workbench/index.html` 在 `data/content.js` 后面加载 `data/screens.js`。
4. **首批内容**：关卡模式 11 个页面，`game: "in_use"`，跳转按下表（2026-10-23 游戏仓库 `game/app/boot.gd` 的现状；模块隔离队列的 CORE-02 之后这段代码会搬到 `game/modes/lab/`，行为不变）：

   | 页面 | 操作 | 去向 |
   |---|---|---|
   | lobby 大厅 | focus 0 继续 | 有上次关卡 → play；没有 → chapters |
   | lobby | focus 1 | chapters |
   | lobby | focus 2 设置 | settings（Esc 回 lobby） |
   | lobby | focus 3 退出 | @quit |
   | chapters 章节 | ArrowLeft / ArrowRight | 换章（@stay） |
   | chapters | Enter | levels（章节已开放时） |
   | chapters | Esc | lobby |
   | levels 关卡选择 | ArrowUp / ArrowDown | 选关（@stay） |
   | levels | Enter | 有没看过的规则 → rulecard；否则 → play |
   | levels | Esc | chapters |
   | play 局内 | Esc | pause |
   | play | H | hint（第 1 级） |
   | play | Z / R | 撤销 / 重来（@stay） |
   | play | 过关 | complete |
   | pause 暂停 | focus 0 / 1 / 2 | play / hint / play（重来） |
   | pause | focus 3 / 4 | levels（跳过本关）/ levels |
   | pause | focus 5 | settings（Esc 回 pause） |
   | pause | focus 6 | lobby |
   | pause | Esc | play |
   | hint 提示 | H 或 Enter | 下一级（1→3，@stay）；第 3 级时 focus 0 演示、focus 1 回到正确一步，都 → play |
   | hint | Esc | play |
   | rulecard 规则卡 | Enter / Esc | 还有规则卡 → rulecard；否则 → play |
   | complete 过关 | focus 0 | 有下一关 → play；否则 → levels |
   | complete | 其他项 / Esc | levels |
   | settings 设置 | ArrowUp / ArrowDown 选项，ArrowLeft / ArrowRight 调值 | @stay |
   | settings | Esc | @return |
   | controls、dialogue | Esc | lobby |

   菜单项的文字从实际画面上读，不照这张表编。画面对照：lobby → `ui.screen.lobby`（变体 `hub_start` 新玩家、`lobby_generic`、`lobby_story`）；chapters → `ui.screen.chapters`；levels → `ui.screen.levels`；play → `ui.screen.hud_keys` 加场景（局内画面，HTML 只能展示，不能玩）；pause → `ui.screen.pause`（变体 `pause_help`）；hint → `ui.screen.hint`（3 级，focus 0–2 对应第 1–3 级）；rulecard → `ui.screen.rulecard`（变体 `rulecard_how`）；complete → `ui.screen.complete`（变体 `clear_found`）；settings → `ui.screen.settings`（变体 `settings_help`）；controls → `ui.screen.controls`；dialogue → `ui.screen.dialogue`。

   其余画面（配送 `reels` / `settlement` / `settlement_fail` / `shop` / `observe` / `confirm` / `hint_animal` / `delivery_*`，一局 `run_*`，剧情 `story_*`，伙计 `crew_*`）先建条目：填 `art`、`name`、`flow`，`game: "not_yet"`，`transitions` 留空，等 WB-13。
5. **工作台「场景与界面」页加「界面清单」标签**，作为默认标签：
   - **清单表**：按 `flow` 分组，列出名称、五步进度（每步一个小标记，可点：HTML 画面 → 打开画面；Godot → 显示 coverage 条目）、「从哪里跳来 / 能跳到哪里」。可搜索。「所属模式」一列：ART-07 合并后从它的归属数据读（看 ART-07 交付写在哪），没合并时显示「未标」。
   - **单页** `#screen/<id>`：大图（代码绘制，遵守 WB-08 的限帧规则）、变体切换、五步进度、进出跳转列表（可点）。
   - **流程图**：用同一份数据自动生成方框和箭头，纯 SVG，不引第三方库，按 `flow` 分列；点方框打开该页面。
   - 原来指向界面的入口都改指这里：场景页的「游戏界面」分组、资源库里界面画面的详情（加「在界面清单中打开」）、「界面风格提案」标签。
   - 总览页补上「Godot 未实现的界面 N 个、游戏未接入 N 个」。
