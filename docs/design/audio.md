# 声音制作规范

背景音乐当前搁置，工作台只显示音效菜单。以下为合成参数、版本与用户确认约定。实际状态由 audio/export/manifest.json 推导。

## 1 风格总则与可测量标准

这是休闲解谜游戏。声音帮助玩家知道动作生效，并陪伴思考。主音色用正弦波、三角波、经过低通的柔和脉冲波；脉冲占空比只用 0.25 或 0.5，不用未经滤波的硬方波、尖啸、惊吓、警笛或持续白噪声。合成器由 WB-02 实现为仓库内的小型确定性合成器，采用明确命名的参数和音符数组；不引入 sfxr/ZzFX/BeepBox 的不透明位置数组或运行时在线服务。这延续用户指定的程序芯片合成方式，不要求依赖某个第三方实现。

以下数值是本项目的制作目标，不能代替用户听感确认：

| 项目 | 必须满足的规格 | 如何测量 |
|---|---|---|
| 文件 | 44,100 Hz、单声道、16-bit PCM WAV；第一批统一 WAV，暂不生成 OGG | 读取 WAV 头；拒绝非有限样本、越界参数、采样文件引用 |
| 音高与高频 | 有音高声部基频 65–1760 Hz；低通截止不超过 4000 Hz；噪声输入的总能量占各声部混音前能量之和不超过 8% | 校验音符和滑音全程频率、滤波参数；渲染器分别累计滤波后各声部平方和，报告噪声占比。噪声不作音高基频检查 |
| 包络 | 有声事件 attack ≥ 8 ms、release ≥ 25 ms；单次音效不超过 1600 ms（具体清单更短）；不做突变音量或硬切断 | 源参数范围校验；采样端检查非循环音效首尾绝对值 ≤ 0.001；循环素材按接缝检查，音乐不在文件首尾强加淡入淡出 |
| 音效响度 | 活跃段 RMS 为 −24 ± 2 dBFS；同一试听音保持固定强度 | 活跃段指首个至最后一个绝对值 ≥ 0.001 的样本，包含中间留白；全静音失败。对这段按下面公式计算，不拼接重复播放后测量 |
| 音乐响度 | 一个完整循环 RMS 为 −26 ± 2 dBFS；最大与最小的非静音 3 秒窗 RMS 相差 ≤ 6 dB，静音窗低于 −50 dBFS 不参与此项；整曲无 ≥ 1 秒的完全静音 | 分析完整 WAV 与步长 1 秒的 3 秒窗；显示窗口最大差值。响度不合格应改编配/增益，不能靠播放器偷偷归一化 |
| 峰值 / 直流 | 所有文件采样峰值 ≤ −9 dBFS；样本均值绝对值 ≤ 0.001；禁止削波 | `peak_dbfs=20×log10(max(abs(x)))`；`rms_dbfs=20×log10(sqrt(sum(x²)/N))`，x 为 int16/32768。均值直接在归一化样本上计算；报告明确叫 RMS，不冒称 LUFS |
| 节奏与循环 | 64–108 BPM，4/4 拍，每首 32 小节（约 71–120 秒）；最多 6 个声部、同时有音高声部最多 4 个 | 采样数 `N=round(44100×32×4×60/BPM)`；音符开始/结束都从绝对拍数独立换算，不累加取整误差 |
| 循环接缝 | `abs(x[0]-x[N-1]) ≤ 0.002`；`abs((x[1]-x[0])-(x[N-1]-x[N-2])) ≤ 0.002` | 对最终 PCM 做数值检查；再连续听 3 圈接缝和 10 分钟低音量循环，不能有爆音、明显抽吸或突然停顿。数值通过不等于用户听过 |

每首音乐使用整数种子。渲染循环时先预滚一整圈使滤波和尾音状态稳定，再取下一整圈；跨边界音符按周期调度，禁止用一段硬截断的混响掩盖接缝。若仍不达标，应改音符尾音/编配并重渲染，不能放宽指标。

资源预算适用于将来的工具：默认一首一首生成、一个 worker，数值库线程 1；全机同时最多 2 个耗资源任务和 2 个计算 worker。试听默认低音量，播放器不自动播放；切到后台页或离开声音菜单即停止试听。

## 2 全游戏通用音效

**建议不做普通走路声**：连续移动保持安静；爬梯只低频提示，推箱/挖掘/倒沙各有成功声。`walking_sfx: silent` 是明确的设计规则，不是漏做 `sfx:step`。音效不用按地图再做一套。

本地编号只用小写字母、数字、下划线、连字符；正式 uid 是 `sfx:push`、`music:dungeon_a`。需求举例中的 `sfx.push`、`music.dungeon` 仅指音效/曲组概念，不作为另一套可在代码里混用的 uid。曲组的稳定 uid 见第 3 节。

额外的混音和触发约束：

- 全局最多 **3 个音效实例**；音乐独立计数，最多同时存在 2 条交叉淡化流。音效总线固定 −6 dB，用户滑块只再衰减、不增益；音乐淡化权重之和 ≤ 1，最终不得超过 −1 dBFS。试听和未来游戏都遵守，不能因连按叠出大音量。
- `priority` 为 0–3，越大越优先。超限时新事件仅可替换最低优先级中最老的实例；同优先级也替换最老实例，替换做 25 ms 释放，释放实例仍占上限，先释放后再开始新声。`crate_land` 最多 2 个，其余 uid 最多 1 个；同一物理结算的相同 uid 合并。
- 音效按“状态真正改变”播放，不按按键次数或每个模拟 tick 播放。撤销不倒放动作声，实时配送无撤销，不改变玩法规则。目标灯灭掉静音；再次亮起受限频约束。
- 同一业务事件优先用专用声：过关取代最后一盏目标灯；购买取代金币/普通确认；重开取代普通确认；菜单打开/关闭取代确认/返回；规则卡取代菜单打开；送达取代普通确认。并非同一业务事件的受伤与货损可各叫一次。需要拒绝操作时只叫 `blocked`，自动物理失败不刷拒绝声。
- `reel_spin` 是 400 ms 的可循环音效，首尾同样检查接缝，三滚轮共用 1 个实例，循环总时长上限 2000 ms。即使滚轮还转也自动安静；停下、取消、离开页面时做 80 ms 淡出。重转不叠加旧循环。
- 动物提示和喂零食各一声，中间至少间隔 500 ms；不按地图或动物种类新增叫声资产。音效音量为 0 时试听也为 0，不能临时越过静音。

## 4 源文件、生成、版本与用户确认

### 4.1 文件和数据契约


| 路径 | 内容和写入方 |
|---|---|
| `audio/source/sfx/<id>.json` | AUD-01 写合成参数；如 push.json 对应 sfx:push |
| `audio/source/music/<id>.json` | AUD-02 写音色、原创音符与编排；如 dungeon_a.json 对应 music:dungeon_a |
| `audio/export/preview/<sfx或music>/<id>.wav` | build 生成当前候选，只供工作台试听 |
| `audio/export/manifest.json` | build 生成：每个 uid 的 current（version/hash/wav/sha256/metrics）、所有 approved 版本，以及由确认记录推导的曲组 bindings |
| `audio/export/approved/<sfx或music>/<id>@v<N>.wav` | approve 保存的确认版本，不覆盖旧版 |
| `audio/history/<sfx或music>/<id>@v<N>.json` | approve 保存的源快照和渲染器指纹，永久保留 |
| `audio/approvals.json` | `pushbox.audio-approvals/1`、仅追加 records；与美术记录完全独立 |
| `workbench/data/audio.js` | build 生成工作台数据；离线 file:// 页面可加载。只读取 audio 专属数据，不修改美术 bundle |

源文件公共字段：`format: pushbox.audio/1`、`kind: sfx或music`、`id`（本地号）、`uid`、`name`、可选 `description`（说明字符串）、`seed`（uint32）、`engine: portitor-chip/1`、`sample_rate:44100`、`channels:1`、`version`、`content_hash`、`gain_db`、`instruments`。version/content_hash 只由 build 管理，新源可写 version:0、content_hash:null，首次构建成为 v1。每个 instrument：`id`、`wave:sine|triangle|pulse|noise|pluck|fm|saw`、`pulse_width`（仅 pulse）、`gain_db`、`lowpass_hz`、`attack_ms`、`decay_ms`、`sustain`（0–1）、`release_ms`。未用到的可选字段省略，工具拒绝未知字段。音量参数限 −60–0 dB；滤波截止 200–4000 Hz；decay 0–500 ms；attack 8–200 ms；release 25–1500 ms。白噪声用 seed 驱动的固定 xorshift32，seed=0 映射为 1，不用 Math.random、日期或外部文件。

WB-04 可选音色字段（所有数值必须有限，未填时采用表中默认值）：

| 字段 | 范围 / 默认值 | 适用和含义 |
|---|---|---|
| `pluck_brightness` | 0–1 / 0.6 | 仅 pluck；弦环滤波的亮度，越大高频衰减越慢 |
| `pluck_decay_ms` | 50–8000 ms / 1800 | 仅 pluck；弦振幅自然衰减到约 −60 dB 的时间，仍受门限和 release 包络约束 |
| `fm_ratio` | 0.25–16 / 2 | 仅 fm；调制振荡器频率 / 载波频率 |
| `fm_depth` | 0–12 / 2 | 仅 fm；初始调制指数（弧度） |
| `fm_decay_ms` | 1–5000 ms / 300 | 仅 fm；调制指数指数衰减的时间常数 |
| `vibrato_hz` | 0–12 Hz / 0 | 所有有音高波形；颤音频率，0 关闭 |
| `vibrato_cents` | 0–100 音分 / 0 | 所有有音高波形；颤音峰值幅度，校验上下极值仍在基频范围内 |
| `vibrato_delay_ms` | 0–5000 ms / 0 | 所有有音高波形；延迟后以 100 ms 渐入颤音 |
| `breath` | 0–0.5 / 0 | 仅 sine / triangle；混入低通气声的振幅比例；单独累计滤波后气声平方和计入噪声指标 |
| `echo` | 省略为关闭 | 每件乐器的 `{delay_ms:1–1500, feedback:0–0.85, mix:0–0.5}`，三个字段都必须填写；mix 是干湿比例 |

整首音乐可选 `reverb:{size:0–1,mix:0–0.5}`，两个字段都必须填写；省略为关闭。size 控制四个并联梳状反馈延迟的长度和衰减，mix 是干湿比例。回声先于混响；循环按周期输入预滚至少一整圈，并按反馈衰减长度增加预滚，保留上一圈的效果尾巴；非循环试听只输出文件时长内的自然尾巴，不自动延长游戏音效。效果与乐器增益都参与最终峰值、响度和接缝检查。拨弦使用固定种子的噪声激励形成有音高的弦共振，按有音高声部计数；独立 noise 波形与 breath 气声计入噪声能量。

`audio/presets.json` 是 `pushbox.audio-presets/1` 格式，`presets` 按试听顺序存放具名乐器参数。引用例如 `{"id":"lead","preset":"guzheng","lowpass_hz":1800}`：先展开预设，再按源 instrument 的同名字段覆盖；echo 对象也整体覆盖。预设不包含 id，不支持预设套预设。展开后仍做全部字段、波形适用范围和数值校验；不存在的名字报 instrument.preset 错误。预设库内容参与渲染器指纹，因此更新预设会使当前候选重新升版，历史确认仍按保存的指纹核验。

`node tools/audio.mjs presets --out docs/packages/WB-04/presets` 输出 18 个最长 4.8 秒的独立试听 WAV 和按预设表顺序串联的 `all.wav`，段间严格留 0.5 秒。旋律类共用同一短句，打击类共用一组节奏；低音预设降八度，底鼓以同组节奏做下滑音。试听是演示文件，不写声音清单、源文件或游戏；命令打印每个样本的实际增益和指标问题，指标未通过的样本明确标记为未验证，不能作为合格候选。

音效另有 `duration_ms`、`events`（`instrument`、`start_ms`、`duration_ms`、`note` MIDI 整数或 noise 时省略、可选 `slide_to_note`、`gain_db`）；event.duration_ms 是发声门限，尾音 release 也必须计入文件总时长。reel_spin 另有 `loop:true`。音乐另有 `set`（dungeon/diyu/jeju）、`bpm`、`meter:[4,4]`、`bars:32`、`mode`（说明文字）、`tracks`（每轨 `instrument`、`notes:[{beat,length,note,gain_db}]`，beat/length 为四分音符拍数，最多 1/16 拍精度）。beat 范围 [0,128)，length>0，跨圈音符尾音按周期合成。音高 MIDI 36–81，并检查滑音全程在基频范围内；noise 不填 note。首批不做随机演奏变体、导入外链乐谱或人工音频后期处理。每首的旋律/节奏要在本仓库原创写入 notes。


### 4.2 生成和版本

`node tools/audio.mjs build [--root <目录>] [--kind sfx|music] [--baseline-ref <Git引用>]`：按 uid 排序，规范化 JSON 对象键（数组顺序保持），将所有影响声音的参数、渲染器源码指纹、采样格式纳入 SHA-256。name/description/自动维护字段不影响声音哈希。源数据或渲染器改变时 hash 变。制作包每次 build 都显式传 `--baseline-ref origin/<包头实际基线>`：工具只读该 Git 引用的同 uid 源文件 version/content_hash，记为发布基线；该引用中没有源则基线 v0。当前声音 hash 与基线相同，保留基线版本；不同则目标版本恒为基线+1。新音源不论改参数重建几次，交付始终 v1；已有音源反复迭代最多基线+1。工具写回目标版本，不要求制作方手改 version。`bumped` 计版本数字增加项，另报 `changed` 计声音 hash 改变项，两者不能混淆；第二次相同输入重建必须 0 bumped / 0 changed。未传 baseline-ref 时按当前源已存的 version/hash 增量工作，适合独立构建，制作交付不得用它替代锁定基线。若目标版本已存在不同 hash 的用户确认记录，拒绝构建并报告“发布基线已过期”，不可复用确认版本号。Git 引用不存在或读取失败也必须拒绝，不能默认为 v0。同一份源、同一版本渲染器和运行时连续构建两次的 PCM 与 WAV SHA-256 必须相同，WAV 不写时间戳。构建缓存不得掩盖对确定性的测试。

`--kind` 只更新这一类 preview、源文件版本及该类历史清单，汇总 manifest/audio.js/id-map 仍由完整已有文件合成，不清掉另一类。AUD-01/02 可各自制作；共同生成清单由 Claude 合并后重建。改变渲染器相当于所有依赖声音换版本，WB-02 之后修工具要另走包和确认，不能自动沿用批准。

`node tools/audio.mjs verify [--root <目录>] [--kind sfx|music] [--require-sources]`：重算 hash、重渲染比对 WAV、检查第 1 节和清单时长/声部/频率/循环指标，验证历史与确认 WAV 的 sha256；缺源可显示“未制作”，不伪装为已验证。加 `--require-sources` 时，本类清单任何一项缺源、漏导出或参数/指标不合格均非 0 退出；未确认本身不使候选 verify 失败。工具报告必须区分“指标通过、未确认”与“可以进游戏”。


### 4.3 确认和选曲

只有用户可以确认。工作台试听、默认单选、点击“想用这首”、数值合格都不是确认。制作方不得运行 approve。用户可以只确认某首候选“质量通过”而暂不选作地图用曲；**音频确认和地图采用必须分别记录**。

工具实现后，Claude 根据用户原话使用以下接口记录（示例不表示授权）：

```bash
node tools/audio.mjs approve --items sfx:push@v1 --by 用户 --via chat --note '用户对具体版本和哈希的确认原话'
node tools/audio.mjs approve --from-file audio-approval-request.json --by 用户 --via workbench
```

确认请求格式 `pushbox.audio-approval-request/1`：`items:[{uid,version,hash,wav_sha256}]`；可选 `selections:[{set_uid,uid,version,hash}]`，set_uid 如 music:dungeon，uid 如 music:dungeon_b。选曲请求中的音频必须在同一请求 items 中，或已存在完全匹配的确认记录。请求内容在工作台“复制确认文字/下载确认请求”里完整列出，Claude 核对原话确实含“采用”再记录 selections；没有采用原话不能自动写 bindings。

`approve` 对 items 的新质量确认要求 source 已 build 且与 current 的版本/hash/WAV sha 完全相符、来源通过 verify；否则拒绝。selections 可独立采用已有批准历史中的某个版本，即使 current 已是未确认 v2，也允许显式选回批准 v1；此时核对历史源/hash/批准 WAV 完整性与本曲组归属，不要求它等于 current。缺用户原话、错组、未知 uid、历史缺失/损坏均拒绝且不部分写入。记录字段含 `id:AAP-0001…`、时间、by/via/note、items、selections；每个 item 含 uid/version/hash/wav_sha256/历史源和确认 WAV 路径。相同已记录请求提示已记录，不重复追加；同一请求内冲突选择拒绝。更换曲组选择通过新的用户采用记录追加，旧记录和媒体保留，最后一条有效 selection 生效。遍历全部确认历史后，该曲组从未出现有效 selection 才为空；后续仅质量确认而没有 selections 的记录不清除既有绑定，不以候选次序代替选择。
