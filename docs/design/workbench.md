# 美术工作台（公开版）

本文记录 WB-08–WB-13 已交付的公开工作台结构，以 2026-10-23、WB-13 合并后的实现为基线；页面数量和完成进度以当前界面清单、资源 manifest 和 native coverage 为准。相关交付见 [WB-08](../packages/WB-08.md)、[WB-09](../packages/WB-09.md)、[WB-10](../packages/WB-10.md)、[WB-11](../packages/WB-11.md)、[WB-12](../packages/WB-12.md)、[WB-13](../packages/WB-13.md)。

## 1. 定位与打开方式

工作台是本仓库美术、地图概念、声音和界面外观的查看、比较与确认入口。双击 [`workbench/index.html`](../../workbench/index.html) 打开，默认进入总览；也支持通过 HTTP 打开。页面使用静态 HTML、CSS、JavaScript 和随仓库提供的数据，不引入前端框架，也不要求先启动构建服务。

公开工作台展示公开美术、示例画面和已登记的页面导航。原样预览使用公开示例设计模型，不能真正游玩，也不是游戏 SDK；技术检查、默认选择和预览可打开都不能替代用户对具体素材 id、版本和哈希的确认。

WB-15 已增加“文档”入口，可在网页内搜索阅读设计文档；玩法设计目录为 `docs/design/gameplay/`。

## 2. 六个一级入口

左栏只保留六个一级入口，编辑、导出等工具通过资源详情或页内入口进入。

| 入口 | 地址 | 内容与用途 |
|---|---|---|
| 总览 | `#home` | 当前资源与声音数量、素材状态、最近三个确认批次、内容缺口和快捷入口。 |
| 资源库 | `#library` | 合并资源入口，按模式、主题 / 地图、用途、资源类别、确认状态、搜索和通用资源筛选，点击卡片看详情。 |
| 场景与界面 | `#scenes/screens` | 默认显示界面清单，页内可切场景预览、流程图、界面风格参考，并打开原样预览。 |
| 确认 | `#review` | 查看确认清单、批次和放大预览；导出位于 `#review/export`。 |
| 地图概念 | `#concepts` | 按阶段、评价和完整度查看概念；没有概念场景的地图默认折叠，显示实际场景有无和静态图数量。 |
| 声音 | `#audio/sfx` | 当前主入口为音效查看与主动试听，模式声音筛选保留对应集合；音乐与按地图保留旧地址，菜单仍隐藏，背景音乐继续搁置。 |

资源库筛选写入 URL，刷新、分享地址和浏览器后退可恢复筛选。旧资源、模式、导出和界面提案地址保留兼容跳转；界面清单为 `#scenes/screens`（`#scenes` 同页），单页固定地址为 `#screen/<id>`，流程图为 `#scenes/flow`，场景预览和风格参考分别为 `#scenes/preview`、`#scenes/references`。

资源和场景详情在窄窗口使用可关闭的抽屉，关闭后回到原卡片；宽窗口保留详情栏。确认页按打开时的待确认数量选择初始筛选，没有待确认素材时给出说明和已有批次入口，不以空白表示完成。

## 3. 列表与代码预览

列表使用已生成并提交的 `art/export/preview/<id>.png`，界面清单也直接显示对应的预览 PNG。资源库和确认页共用缩略图逻辑：精灵从图集中裁切首个动画的首帧；本地精灵草稿仍用 canvas 展示实际草稿，PNG 加载失败时回退到原代码绘制，并对同一资产只警告一次。

点击资源卡片进入详情、点击确认页的放大预览，或打开界面单页后，大图使用代码实时绘制。缩略图与大图遵守同一画法和像素口径；像素图使用最近邻和整数倍缩放，不因列表提速修改已确认素材。

资源库与确认页搜索使用 150ms 防抖；筛选和清除筛选复用卡片节点，更新可见性。列表不为每张卡片运行实时动画。

## 4. 预览调度与性能门槛

共享 `PBStage` 默认以 8fps 调度过程式代码预览；精灵仅在动画帧变化时重画。连续三次绘制耗时超过 40ms 时降到 4fps，连续三次超过 120ms 时降到 2fps。只有当前播放者能运行，离屏、页面隐藏或所在工作台页隐藏时停止；输入、焦点或显式帧变化仍可立即刷新。

原样预览在消费端进一步限帧：原有关卡模式十一页中，章节、暂停、规则卡、过关、设置和操作说明为 2fps，其余为 4fps；新增普通页为 1fps，滚轮与结算为 2fps，教学列表为 0.5fps。这些设置不修改共享 `PBStage` 的默认值或自动降帧阈值；切页销毁旧 stage，离开页面停画，浏览器恢复缓存页面时重建。

[`tests/workbench.perf.cjs`](../../tests/workbench.perf.cjs) 保留以下门槛和报告口径。CPU 由 CDP 的 `TaskDuration` 与 `Timestamp` 差值计算，闲置采样约三秒；机器、协议和页面状态会影响实测值，交付应保留本机结果与未达项。

| 检查范围 | 门槛与处理 |
|---|---|
| 原五个列表：配送全部、配送地府、配送界面、全部资源、确认全部；新增界面清单与流程图 | 闲置 CPU 必须 `<5%`，打开页面最长长任务必须 `<200ms`。 |
| 配送资源库、全部资源库、确认页的搜索和状态筛选 | 最长长任务必须 `<100ms`。 |
| 工作台主角代码预览，以及原样预览所测的普通关卡页面 | 闲置 CPU 必须 `<10%`。 |
| 指定重画面：滚轮、结算、关卡选择；原样预览中的关卡选择 | 闲置 CPU `<30%` 是可选目标，保留实测报告，未达不能改画法或降低阈值。 |
| 原样预览所测的十一页切换 | 记录切换耗时和最长长任务；普通页最长长任务必须 `<250ms`，关卡选择作为重画面报告。 |

“最长长任务为 0”只表示未观测到至少 50ms 的长任务，不表示执行耗时为零。重画面的可选目标未稳定达到时应如实保留结果；新增普通页仍按 `<10%` 强制门槛采样验收，不能把重画面例外扩展到所有预览。

## 5. 界面清单是唯一入口

界面登记源为 [`content/screens/screens.json`](../../content/screens/screens.json)，由 [`tools/screens.mjs`](../../tools/screens.mjs) 校验并生成 `workbench/data/screens.js`。界面清单、单页、流程图、总览和原样预览共用生成数据；不手改生成数据，不在各页面另建一份进度表。

截至 WB-13，清单有 42 个逻辑页面、7 个画面变体，覆盖全部 49 项 `ui.screen.*`；49 项是素材画面数，不能称为 49 个逻辑页面。逻辑页面按“开始、关卡内、配送一局、剧情、伙计、设置与帮助”分列，主图与变体保持对应关系。

五步进度按“设计 → HTML 画面 → 用户确认 → Godot 实现 → 游戏接入”显示，各步有独立依据：设计来自清单登记，HTML 来自 manifest 中的实际素材，用户确认读取当前素材的确认状态，Godot 来自 `godot/native-coverage.json` 的 `implemented` / `reference_only` / `missing`，游戏接入由清单的 `in_use` / `not_yet` 人工字段维护。“只有参考图”不等于 Godot 已实现，素材已安装也不能证明某个页面已接入游戏。

主图与变体分别读取画面进度；变体没有独立游戏接入登记时，不能从预览可跳转推断接入完成。模式归属按 ART-07 的独立元数据维护，界面清单不添加或推断 `owner`，缺少归属数据时显示“未标”。

跳转登记只包含公开的按键 / 按钮、焦点、目标、简短条件和画面热点。主图 `transitions` 与已有独立绑定的大厅变体 `variantTransitions` 分开；热点按实际 320×180 画面量取，纯键盘动作不虚构按钮，自动过关不虚构游戏按键。没有可靠去向的动作保留 `@stay` 或不绑定，`notes` 标明待定并保留 `sources` 的文件与小节；来源引用不等于允许搬入私有原文。

运行 `node tools/screens.mjs build` 更新生成数据，运行 `node tools/screens.mjs check` 检查素材覆盖、引用、目标、键和热点。工具不会构建美术或新增素材确认；校验通过只说明登记满足检查，不能替代设计裁决、游戏验收或资源发布。

## 6. 原样预览

[`workbench/play.html`](../../workbench/play.html) 是独立页面，从总览或场景与界面入口打开。默认只有居中的 320×180 画布，按窗口可容纳的最大整数倍放大，使用最近邻和黑边，不显示工作台左栏、工具条或信息层。

按 I 打开或关闭信息层，可看本页按键、五步进度、焦点、提示级别、条件开关和跳转历史，并切换关卡 / 配送模式或已登记的大厅画面。键盘和鼠标热点按当前主图或独立变体的跳转表执行；URL 保存页面、焦点、模式等预览状态，浏览器返回保留来源历史，Tab 保留浏览器焦点移动。

配送预览从滚轮台进入，配送 HUD 只作展示，C 仅在预览中模拟送达后进入结算；关卡画面中的 C 仅模拟过关，Z / R 提示预览不能真正游玩。条件开关用于查看设计分支，待定动作留在本页并显示待定说明；缺图目标显示占位卡，不能用占位或模拟行为声称功能已进游戏。

## 7. 新页面的登记顺序与验收边界

所有新页面先进入 `content/screens/screens.json`，确定逻辑页面、主图 / 变体、公开说明和固定地址，再画 HTML 画面供用户查看；Godot 实现以 HTML 为画面对照，游戏接入须有用户对具体素材的确认。缺少设计决定、用户确认或接入证据时保留相应未完成状态，不能用测试通过或默认选择补齐。

美术规范、界面风格、声音和工作台设计只在本仓库 `docs/design/` 维护。公开文档不复制私有工具页面或游戏数据；素材确认、Godot 技术验证、游戏可玩性验收和固定资源版本发布各自独立，工作台展示的进度不合并这些结论。
