# 美术规范（AD-1）

适用于全部游戏美术与界面。规范只描述规则；每件资产的具体版本和确认状态以 `art/` 中的数据与确认记录为准（见 [美术流程](art-pipeline.md)）。

## 1 原则：玩法信息优先

画面上的视觉强度按以下顺序递减。任何装饰都不能比它的上一级更醒目：

1. **人物**：唯一的暖色高饱和组合（黄帽、红衣），四周 1px 深色描边。
2. **可操作物与目标**：箱子、门、压板、目标槽、出口旗、收集斗。用清楚的轮廓和形状区分，配对关系用**形状符号**（圆、三角、方块）表达，颜色只作辅助。
3. **会动的材料**：沙、水、酸、烟、火、冰。每种材料必须同时在色相和纹理上与其他材料不同（不能只差明度）。
4. **静态地形**：基岩、夯土、裂岩。顶面 1px 受光边，底面 1px 阴影，不加黑色描边。
5. **背景与装饰**：低对比、偏冷、偏暗；任何背景像素都不能比同一区域地形的中间调更亮；不出现与可操作物形状相近的装饰。

## 2 规格

| 项 | 规定 |
|---|---|
| 逻辑画面 | 320×180，整数放大，最近邻采样，不做亚像素位移或抗锯齿 |
| 格子 | 16×16；人物、箱子和机关精灵为 16×16，有需要时可用 16×32 或 32×16 |
| 锚点 | 精灵锚点为底边中心 (8,16)，与所在格的底边对齐；界面元素锚点为左上角 |
| 调色板 | ENDESGA 32（作者 Endesga，公开免费使用），源数据用单字符 `a`–`z`、`A`–`F` 编码，`.` 表示透明 |
| 光照 | 主光来自左上；立体物件右下侧暗一级 |
| 描边 | 人物、箱子、可拾取物用 `z`（#181425）描边；地形与背景不描边 |
| 动画帧率 | 人物动作 8 fps；环境与装置循环 4 fps；界面过渡按整数像素移动 |
| 字体 | Fusion Pixel 12px（OFL），最近邻渲染，关闭抗锯齿与 hinting；正文行高 14px |
| 图标 | 16×16；按键图标 13×13 |
| 面板 | 九宫格，角 6px；面板底色不透明，不用渐变 |

## 4 动画清单要求

- 人物：待机 2 帧、走 4 帧、推 4 帧、爬 2 帧、挖 3 帧、倒 3 帧、落 1 帧、胜利 2 帧；左右镜像共用。
- 机关：门开 / 关各 4 帧；压板按下 1 帧；目标灯亮 2 帧循环；收集斗刻度。
- 反馈：受阻抖动（人物左右 1px，2 帧）、灰尘（落地 3 帧）。

## 5 地形着色规则（游戏内由着色器实现）

地形逐 cell（=逐像素）着色。HTML 中的实现在 `workbench/js/core/terrain.js`，它就是规范：

- 静态材料（基岩、夯土、裂岩）的颜色只由材料、像素位置哈希 `h32(x, y, 材料种子)` 以及上下左右的同类关系决定。游戏着色器必须使用同一哈希公式，以保证逐像素一致。
- 沙、水等会移动的材料在游戏中使用 SDK 的随机颜色位（随格移动），与 HTML 只比对颜色集合，不要求逐像素一致。
- 受光边：上方为空（或非同类）的格画 1px 亮色；阴影边：下方为空的格画 1px 暗色。
- 水面：上方为空的水格画 1px 亮线，水体比静止背景亮。

## 6 主题与生态

六个主题（`theme.dungeon` / `ruins` / `cave` / `forest` / `sky` / `cosmos`）各有一套地形图案、背景和生态清单，全部参数在主题资产的 `params` 中。生态是装饰，规则如下（实现见 `workbench/js/core/ambient.js`）：

- 每个主题 2–4 种：1–2 种植物 + 1–2 种小动物。每个房间植物最多 3–4 株。
- **会动的小动物每个房间最多 1 只，而且不是每关都有**：每种动物有自己的出现概率（老鼠 15%，蝙蝠、知更鸟、蝴蝶、白鸽、无人机约 35%，飞蛾 45%），按关卡编号固定决定这一关有没有、是哪一种，约三分之一的关卡会出现。大厅和章节卡固定放 1 只；「代表场景 · 全要素」为审稿显示全部。
- **飞行生物**（蝙蝠、飞蛾、蝴蝶、白鸽、云灵、无人机）画在地形后面，只出现在空格背景中，永远不挡住人物、箱子和机关。
- **地面生物与植物**（老鼠、甲虫、知更鸟、花草菇晶）画在地形之后、实体之前：人物和箱子经过时会挡住它们。它们只出现在开局时就空着、且不是机关或目标的格上；放置位置由格子坐标哈希决定，不随局面跳动；所在格被箱子或沙占据时不再显示。
- 生物不发光晕、不发声、不与玩家或物理互动；外形不得与箱子、目标、门等可操作物相似。
- 动作使用整数三角波和固定帧率，任何渲染器都能复现；与参考图逐像素对照时用第 0 帧。
- **地府主题 `theme.diyu`**（候选）：岩石用荒野图案 `wild`（`workbench/js/core/terrain-diyu.js`：深色泥土、地层和田石、枯草顶、根须），背景是荒郊野岭的夜色（残月、荒山、枯树、坟包、招魂幡、鬼火、夜雾）；规则材料（土、裂石、沙、水）的画法和 `terrain.js` 完全一样（第 8 节可读性）。
- **济州主题 `theme.jeju`**（已存在的代表主题）：岩石用图案 `jeju`（`workbench/js/core/terrain-jeju.js`：多孔的黑色玄武岩，房间两边画成圆石墙、最下一行画成礁石，下半屏悬空一格厚的石条画成码头栈道，露天的顶面上半屏是火山土和草、下半屏是闪光的黑沙），背景是白天的海边（晴天、白云、汉拿山和小火山丘、远蓝近墨绿的海、近岸礁石剪影）。背景有地平线，多屏房间按屏行重复（`BANDED` 要加 `jeju`，DLV-05）。天空比第 1 节第 5 条亮，同 `theme.sky` 的先例（用户要"明亮"），所以靠近地形的海和礁石压暗（近处的海比规则水的水体暗）；背景的海不画规则水那道亮水面线。规则材料同 `terrain.js`。默认不刮全屏风线：阵风只画在机关格上（`fx.jeju_gust`）。详见 delivery-jeju.md 第 1 节。

## 7 多语言界面

- 界面上不画任何文字贴图；所有文字由字体实时绘制，来自 `content/i18n`。
- 布局先放固定元素（图标、按键、数值），文字占用剩下的空间：菜单和按钮宽度 = 最长文字 + 图标与留白，并限定在最小、最大值之间。
- 放不下时的处理顺序：换行（段落）→ 省略号（单行标题）→ 隐藏按键说明文字、只留按键图标（底部按键栏）。每次处理都会记录下来；中、英文必须零记录，伪本地化（英文拉长约 40%）只用于提前发现问题。
- 卡片与列表行不放长文字：章节卡用章号、主题徽章和进度，关卡行用编号加省略标题，完整内容放在说明栏。
- 标题在宽度够时用 2 倍字号，不够时自动回落到 1 倍。

## 8 主题地形与可读性

- 主题地形以主题的自然特性为准（石牢砖墙、神庙砂岩、晶窟岩洞、古森草皮褐土、圣域云朵、星站舱板），不为可读性改动主题的风格。
- 可操作或带规则的材料（夯土、散沙、裂岩、水、箱子、门、压板、目标）在所有主题中保持同一外观。其中夯土和裂岩**自带方块轮廓**：外圈 1px 深色边框，左上 1px 亮色倒角。这样即使放在颜色相近的主题地面上（例如森林的褐土、神庙的砂岩），也能一眼看出这是可以挖、可以炸的方块。
- 天空主题的实心台是云朵（白色云团、顶面微起伏、底部阴影、圆角），背景远云更淡，避免把远云误认成落脚点。

## 9 环境效果（光照与天气）

实现见 `workbench/js/core/env.js`，参数在各主题的 `params.env` 中。

- **纯视觉**：不影响模拟与规则，玩家可在设置中选「全部 / 只要光照 / 关闭」。
- **光照只落在背景上**：在画地形之前作用于背景层，地形纹理、夯土、裂岩、箱子、人物、机关的颜色一律不变。做法是沿调色板把像素提亮一级，边缘用 4×4 Bayer 抖动过渡，不用半透明。暗角只压暗画面最外缘。
- **天气每关最多一种**，稀疏、低对比，不画在 HUD 上。关卡可在规格中写 `weather` 指定，不写就用主题默认。
- 各主题：石牢（火把光晕、暗角；余烬 / 滴水）、神庙（斜射光柱与浮尘；沙尘）、晶窟（荧光蘑菇与晶簇的冷光、暗角；默认滴水）、古森（树冠光束、贴地薄雾；雨 / 萤火虫）、圣域（太阳光晕；默认风 / 雪）、星站（暗角；默认流星）。
- 与参考图逐像素对照时关闭环境效果（`level.*.png` 即为关闭状态）；环境效果的观感另行用代表场景审稿。

## 10 不做的事

- 不用 AI 风格的光晕、渐变、柔边、高斯模糊、半透明叠加光束。
- 不用颜色作为唯一的配对信息。
- 背景中不出现可能被误认为可操作物的方块形物件。

## 11 第 2–5 章的材料、机关与特效

着色规则写在 `workbench/js/core/matter.js`（与 `terrain.js` 一样，这个文件就是游戏着色器的规格），精灵在 `art/source/mechanism/`、`art/source/fx/`。工作台「场景」页的「第 2–5 章代表场景」把每章的新元素放进该章主题里一起看。

- **带规则的材料不随主题换皮**：碎石、引信、酸液、软岩、硬岩、轻烟、沉雾、菌塞、木栅、冰在所有主题中外观相同。同色同纹 = 同规则。
- **固体块带外框**：引信、软岩、硬岩、菌塞、冰沿用夯土与裂岩的做法，外圈 1px 深色边，相邻同种材料之间不画边，连成一整块。木栅的上端是尖桩。
- **同一刻纹 = 同一标签**：两种外观的软岩（米白 `L`、灰紫 `M`）每格中央都刻着同一个菱形记号；硬岩没有记号。观察模式中可酸蚀的材料再标一个同形的 `etch` 图标。
- **液体与气体**：酸液是发亮的黄绿色，水面有起伏和上升的气泡；气体是网点（不用半透明），轻烟为浅灰白、向上飘，沉雾为紫色、贴底横移，两者之间能看到背景。
- **机关**：升降台台面有黄黑斜纹（会动的机关），竖井两侧画导轨；按钮是黄色圆钮，和灰色压板区分；收集斗内衬 + 右侧 0–4 格刻度，达标变黄并锁存；开关扳动后保持；火盆、喷口点着或喷气时循环动画；藤梯未浇水时只有根，长出后横档是藤条。
- **水上的木箱**：比原位置下沉 3 px，并在水面画 `fx.ripple`，看起来一半吃水。
- **观察模式**：除第 1 章的类别图标外，新材料再标 `ui.rule_icon`（上浮、下沉、可燃、可酸蚀、冰、慢速粉末）；火盆与喷口的作用区画虚线框（火盆橙色、冷凝青色、热喷口黄色），释放口的格子画紫色虚线框，收集斗画黄色虚线框；开关、按钮到受控机关画点线。
- **特效只是插图**：爆炸、崩落、火焰、水花、结冰闪烁的时机和范围在游戏中以 SDK 结果为准；悬停高亮必须如实显示影响范围，不能用特效代替。
